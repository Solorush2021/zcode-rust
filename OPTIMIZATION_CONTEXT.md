## [ORCHESTRATOR] Language & platform decision (locked, rationale)
**Universal Rust core, not Mac-specific.**
- The hot paths (dispatch, search, parsing, agent orchestration) have zero need for Apple frameworks. Our Rust core already compiles cross-platform (std-only).
- Precedent: fish shell, Zed (Rust core + thin platform shells), Rspack/oxc (universal). Swift/Mac-only would split the codebase for ~0 gain on CLI/agent paths and forfeit Windows/Linux.
- Platform matrix: `aarch64-apple-darwin` (primary), `x86_64-apple-darwin`, `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `x86_64-pc-windows-msvc`. Platform-specific code stays behind small shim modules (process naming, credentials/keychain, notifications).
- Desktop app (Electron) keeps its shell; it already consumes the CLI as agent runtime — it inherits every Rust win automatically. TUI animations are terminal-rendered (not our CPU); UI polish is explicitly LOW priority per user.
- Node stays as the embedded agent runtime (210k lines TS) — shrink its per-spawn cost now (batch fixes), port inward over time.
